# Evaluation QA Set

`qa_set.json` contains a draft 18-case set tied to the NASA/TM-2004-213048 PDF in `data/curated/corpus/`. Its source corpus version is the document SHA-256 recorded in the corpus manifest. The labels are not independently reviewed; therefore the draft is useful for local test development but is not a release gate and its metrics must not be presented as reviewed benchmark results.

Each case must have a stable `id`, a specific `question`, `answerable`, and a source-grounded `reference_answer`. Answerable cases require one or more `relevant_source_ids` resolving to the exact stable identifiers used by retrieval. Unanswerable cases must use an explicit abstention reference and an empty source-ID list. Retrieval precision and recall are macro-averaged over answerable cases only. RAGAS context precision and context recall are likewise scored only on answerable cases, while faithfulness is scored across all cases, including unanswerable ones, so unsupported answers can lower the aggregate. Retrieval-empty and explicit-abstention rates are reported separately for out-of-corpus cases. Increment `dataset_version` when labels change and set `source_corpus_version` to the immutable corpus revision evaluated. Change `label_review_status` to `reviewed` only after an independent reviewer has checked every reference answer and relevant source page. Run `python scripts/validate_qa_dataset.py` to validate corpus checksums, cited pages, case counts, and unanswerable coverage.

The evaluation extra currently constrains `langchain-community<0.4.2` because RAGAS 0.4.3 imports a Vertex AI module removed in later `langchain-community` releases; see the [upstream RAGAS issue](https://github.com/vibrantlabsai/ragas/issues/2745). Recheck this bound when upgrading RAGAS.

Run `python scripts/evaluate_qa.py` after installing `.[evaluation,embeddings,knowledge,llm]`, building the index, and setting `RAG_PHY_LLM__API_KEY`. The runner performs actual retrieval and answer generation, validates the generation JSON contract, then uses RAGAS's Anthropic adapter for the configured metrics. It writes `reports/evaluation/answer_quality_draft.json`; provider errors or malformed model output fail the run. No benchmark result is checked in because this environment has no provider credentials, and draft labels remain marked as draft until independently reviewed.
